**แบบจำลอง + ดีไซน์ · 2026-10-22** · โมเดล: `pasadhi/app/group.py` · กราฟ: `bench/results/fig07_group.png`

## 1. แนวคิด

สำนักงานที่มี 100–200 เครื่อง (desktop + server + notebook) ที่ใช้งานเฉลี่ย ≤ 60 % ต่อวัน
สามารถยก 30 % ของทุกเครื่องให้ PASADHI ภายใต้ **group id เดียว** และ **บริหารกันเองในองค์กร**

```
        ┌──────────── Group grp_7f3a… (join token grp_… ) ────────────┐
        │  controller (เลือกจากเครื่องที่คะแนนสูงสุดใน LAN)            │
        │   ├─ node 001 … node 200   (desktop / server / laptop)       │
        │   ├─ policy: share 30 %, reserve 5 %, time windows           │
        │   └─ local queue: ทำงานต่อได้แม้ WAN หลุด                     │
        └───────────────────────────┬──────────────────────────────────┘
                                    │ aggregate report (ทุก 60 วิ)
                             PASADHI global network
```

- **group id** = ตัวตนของทั้งองค์กร (ใช้คิดเงิน/ออกใบเสร็จ/audit)
- **join token** = ให้เครื่องใน LAN เข้าร่วมได้ โดยไม่ต้องแจก token รายเครื่องให้คนนอกรู้
- **controller** = เครื่องหนึ่งในกลุ่ม (ไม่ใช่เซิร์ฟเวอร์แยก) เลือกอัตโนมัติจากคะแนน; ถ้าเครื่องนั้นดับ เครื่องถัดไปรับหน้าที่
- **autonomy**: งานภายในกลุ่ม (internal queue) ทำงานต่อได้แม้เน็ตออกนอกองค์กรล่ม — เฉพาะงานที่ปล่อยแชร์เท่านั้นที่รอ WAN

## 4. ทำไม 30 % จึงปลอดภัยกับงานประจำวัน

- ระหว่าง 09–18  utilisation เฉลี่ย 65 % → เหลือ 35 % → แบ่ง 30 % ได้โดยเหลือ buffer 5 %
- 18–24 และ 00–09 utilisation 17–22 % → แบ่งได้เต็ม 30 % โดยไม่กระทบ
- ตัวเลขนี้เป็น **ค่าเฉลี่ยของกลุ่ม** — เครื่องที่ทำงานหนัก (server) ใช้ 80 % จึงแบ่งได้แค่ 20 % ระบบจึงคำนวณ
  `usable = min(share, 1 − utilisation)` **รายเครื่อง** ไม่ใช่เหมารวม

## 5. การบริหารจัดการภายในกลุ่ม

| เรื่อง | กลไก |
|---|---|
| ผู้ดูแล | `owner` (1–3 คน) ตั้ง share %, time window, เครื่องที่ห้ามใช้ |
| สมาชิก | เห็นเฉพาะเครื่องตัวเอง + คะแนนสะสม |
| โควตา | แบ่งตามแผนกได้ (เช่น การเงิน 10 %, R&D 50 %) |
| งานภายใน | queue แยก, priority สูงกว่า public เสมอ, ทำงานได้ตอน WAN ล่ม |
| Audit | log ต่อ group id: ใครใช้, กี่ชั่วโมง, ดึง capacity เท่าไร |
| ใบเสร็จ | ออกเป็นราย group (ไม่ใช่รายเครื่อง) เพื่อให้ฝ่ายบัญชีจัดการได้ |

## 6. ความปลอดภัย

- join token หมุนได้ทุก 90 วัน; เครื่องที่ถูกถอดออก (revoke) ใช้ token เดิมไม่ได้
- token รายเครื่อง (จาก `app/identity.py`) ใช้ยืนยัน node → controller; controller เซ็นงานด้วยคีย์กลุ่ม
- งานที่รับจากภายนอกถูก **sandbox** (Job Object/cgroup) และไม่เห็นไฟล์ผู้ใช้ — ต้องทำก่อนเปิดโหมด Shared
- โหมด Internal: ไม่มีข้อมูลออกนอก LAN เลย (ปิด egress ได้ที่ firewall)
